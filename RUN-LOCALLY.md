# Прогон ACP-транспорта в Paseo

Ветка `feat/acp-transport` установлена как локальный плагин вместо npm-версии.

## Что изменилось

Провайдер теперь говорит с `commandcode acp` (Agent Client Protocol) вместо
одноразового `commandcode -p`. Один живой процесс на сессию вместо процесса на turn.

Проверено на `commandcode 1.74.0`:

- картинки идут нативными ACP-блоками, temp-файлов нет
- `session/cancel` → `stopReason: "cancelled"`, следующий промпт продолжает ту же сессию
- `loadSession` + `session/list` — реальная персистентность и resume
- каталог из ~70 моделей, 5 режимов权限, effort приезжают по ACP
- `plan`-обновления кормят Tasks pill (проверено: `pending`/`completed` доходят)

## Что проверить в UI

1. **Порядок в таймлайне.** Текст должен идти над вызовом инструмента, который он
   описывает, а не слипшимся блоком в конце. Это была главная поломка `-p`.
2. **Картинка.** Приложите изображение к промпту — агент должен его увидеть
   (например «What colour is this?» → «Red»). В логах не должно быть
   `paseo-commandcode-attachments` вообще.
3. **Cancel-and-continue.** Начните длинный turn, отправьте второе сообщение.
   Первый turn должен отмениться, второе — продолжиться с контекстом.
   Это **не** steer: `prompt.steer` недоступен, Paseo покажет steer как
   unavailable и отправит новый turn.
4. **Tasks pill.** Попросите «сделай план из 3 шагов» — должны появиться статусы.
5. **Модели и режимы.** Переключите модель и режим (`plan`, `yolo`) — работают из
   ACP-каталога.
6. **Перезапуск сессии.** Закройте агента и откройте заново — история и resume.

## Ожидаемые отличия от `-p`

- Нет авто-заголовка из первого промпта — сессия без имени останется безымянной.
- Нет actionable health-нотиса: если бинарник отсутствует или acp-мод выключен,
  будет generic spawn-фейл или таймаут.
- `-p`-провайдер оставлен в `server/provider.ts`, но **не зарегистрирован** и
  недостижим без правки кода: оба претендуют на id `commandcode`, а хост
  отклоняет дубликаты. Переключать транспорт — только через редактирование
  `index.server.ts`.

## Старые агенты не должны сломаться

У существующих агентов в персистентности лежит `-p`-sessionId
(`{"version":1,"data":{"sessionId":"77c2cee0-…"}}`). Проверено вживую:
`session/load` со старым id проходит без ошибки, и промпт по нему отрабатывает
(`stopReason: "end_turn"`). Форка сессии не будет.

## Откат

```bash
paseo plugin remove commandcode-provider
paseo plugin install npm:@alhassanaraouf/paseo-commandcode-provider
```

## Логи

```bash
paseo plugin logs commandcode-provider
tail -f ~/.paseo/daemon.log | grep -i commandcode
```

Диагностика ACP идёт в stderr с префиксом `[acp]`.
